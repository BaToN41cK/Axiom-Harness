# Приём платежей: ЮKassa

## Где выполняется интеграция

Секретный ключ ЮKassa — это полный доступ к магазину: им можно создавать
платежи, отменять их и читать историю. Документация ЮKassa требует того же
прямо:

> Все запросы к API ЮKassa необходимо отправлять с вашего сервера.

Поэтому ключ живёт **только на доверенном сервере владельца AXIOM**:

```text
desktop (Tauri/React)  →  сервер владельца  →  api.yookassa.ru
     нет ключа              ключ в env           Basic auth
```

Desktop-клиент не хранит ключ, не обращается к ЮKassa и не начисляет баланс.
Локальный процесс и SQLite-файл управляются самим пользователем, поэтому они не
являются границей доверия: иначе любой мог бы записать себе `paid=true`.
`axiom.payments.desktop` отвечает на платёжные команды fail-closed и честно
сообщает это в UI.

## Настройка сервера

Переменные окружения на доверенном backend:

| Переменная | Назначение |
|---|---|
| `AXIOM_YOOKASSA_SHOP_ID` | идентификатор магазина |
| `AXIOM_YOOKASSA_SECRET_KEY` | секретный ключ; префикс `test_` = тестовый магазин |
| `AXIOM_YOOKASSA_RETURN_URL` | https-страница владельца, куда ЮKassa вернёт плательщика |
| `AXIOM_YOOKASSA_DESCRIPTION` | описание платежа, ≤128 символов (необязательно) |

Ключ не читается из `config.json` и не попадает в логи и сообщения об ошибках.
В репозиторий его коммитить нельзя; для тестового магазина это тоже относится —
тестовый ключ даёт доступ к тестовому магазину, а не «ни к чему».

Если переменные не заданы, `build_provider()` возвращает fail-closed провайдер с
пояснением, а не падает: для свежей установки это нормальное состояние.

## Поток платежа

1. `PaymentService.create` записывает заказ в статусе `creating` и вызывает
   `POST /v3/payments` с `capture: true`, `confirmation.type = redirect` и
   `metadata.axiom_order_id`.
2. `Idempotence-Key` формируется как `axiom-<order_id>` — из нашего же
   идентификатора заказа. Повтор после таймаута возвращает **тот же** платёж
   ЮKassa, а не создаёт второй.
3. Плательщик уходит на `confirmation_url`, платит, возвращается на `return_url`.
4. `PaymentService.check` запрашивает `GET /v3/payments/{id}` и начисляет баланс
   транзакционно, ровно один раз (таблица `credits` с первичным ключом по заказу).

Сопоставление статусов:

| ЮKassa | AXIOM | Почему так |
|---|---|---|
| `pending` | `pending` | ожидает действия плательщика |
| `waiting_for_capture` | `pending` | деньги удержаны, но не списаны |
| `succeeded` | `paid` | только вместе с `paid: true` |
| `canceled` | `cancelled` | отменён плательщиком или банком |

Неизвестный статус, валюта не `RUB`, `succeeded` без `paid: true` или платёж с
чужим `axiom_order_id` — отказ, а не догадка. Сетевая ошибка не является
результатом платежа: заказ остаётся в текущем статусе и запрос повторяется с тем
же ключом идемпотентности.

## Тестовый магазин

Тестовые credentials создают платежи в песочнице. Для оплаты подходит тестовая
карта из документации ЮKassa, например `5555 5555 5555 4444` с любым CVC и
будущей датой. Провайдер выставляет флаг `test_mode`, когда ключ начинается с
`test_` — чтобы тестовое пополнение нельзя было принять за реальное.

## Что не реализовано

* **Webhooks.** Сейчас статус подтверждается опросом `GET /v3/payments/{id}`.
  Это работает, но уведомления от ЮKassa экономнее; при их добавлении нужна
  проверка источника и та же idempotency по идентификатору платежа.
* **Возвраты и чеки** (54-ФЗ). Отдельные разделы API, пока не подключены.
* **Аутентификация пользователя.** `PaymentService` принимает `user_id` как
  *доверенный* аргумент: его обязан устанавливать сервер после проверки сессии.
  Передача `user_id` с клиента без аутентификации позволила бы пополнять чужой
  кошелёк.

## Тесты

`tests/payments/test_yookassa.py` — 16 тестов через `httpx.MockTransport`, без
обращений к сети: форма запроса (URL, Basic auth, `Idempotence-Key`, тело),
повтор с тем же ключом, все сопоставления статусов, реальное время списания,
отказы на неизвестном статусе / чужой валюте / `succeeded` без `paid` / чужом
заказе, читаемые ошибки HTTP без утечки ключа, сетевой сбой, fail-closed без
credentials, отклонение `http://` в `return_url` и однократное начисление
баланса при повторном опросе.
